# Existing files and exports

## Inspect the existing artifact

Identify the file type and the user's requested result before adapting it. Preserve the original file, slide ordering, source attribution, authored IDs, notes, and assets unless the user requested a change. Report what was converted and what could not be preserved. Do not reconstruct an existing file from memory or re-emit all its bytes into a tool argument.

| Input | Current contract |
| --- | --- |
| Presentation Markdown | Read and validate its leading settings and fence grammar, then upload the existing UTF-8 bytes. Keep the user's chosen form. |
| Ordinary Markdown | Adapt a copy into presentation grammar. Decide which text belongs on visuals and which is presenter narration; simply adding `presentation: true` can move body text into notes. |
| HTML deck | Adapt a copy into Markdown with `presentation.form: whole-deck` and one HTML fence when preserving its internal slide structure is appropriate. Choose a fence delimiter longer than any matching run in the source. Audit internal notes and sandbox dependencies; external scripts, unrestricted network calls, and arbitrary external assets are not supported by the sandbox. Follow gate one below before offering gate two. |
| PPTX, PDF, DOCX | The document upload endpoint has format converters into the ordinary document model. That does not promise preservation of presentation layout, animations, speaker-note semantics, or editable slide objects. Inspect the conversion and author a deck separately if requested. Do not send binary bytes to the Markdown bulk-upload flow. |

A whole-deck HTML framework must be self-contained within the sandbox's allowed assets. The shared shell offers `strata.deck.registerAdapter({ count, current, goTo })` for whole-deck navigation: `count()` returns a positive integer, `current()` a zero-based index, and `goTo(index)` navigates synchronously. Without an adapter, the host does not know the internal slide count and cannot navigate the framework. An adapter is authored JavaScript, not a fence attribute or an importer that understands every framework. Preserve existing navigation where it works, and explain adaptations or missing dependencies. Check `strata.deck.active` before depending on an active deck shell; an ordinary HTML preview is not a presentation route.

## Gate one: whole-deck before splitting

Run these checks on the final UTF-8 HTML, including any adapter and inlined assets, before writing. Keep the original file and describe every adaptation.

| Rule | Required result | On failure |
| --- | --- | --- |
| W1 Size | Fewer than 524288 UTF-8 bytes, measured after adaptation. | Reduce authorized assets or request a smaller file. |
| W2 Resources | No network or relative `src`, `href`, `srcset`, CSS `url()`/`@import`, fetch, dynamic import, or `new URL` dependency. Fragment references must resolve inside the file; `data:` is embedded. | Inline available authorized local assets, remeasure, and report unavailable assets. Never silently drop them. |
| W3 Libraries | Only the sandbox's documented d3, three, or mermaid URLs may remain external script references. | Inline other available libraries under W1, or report the dependency that prevents presentation. |
| W4 State | No access to `strata.state`, including bracket access or aliases. | Restructure the source; blocks have `{ data, deck }`, not document-state access. |

W3 is a narrow exception to W2 for documented sandbox library URLs, not a CDN exception. Parse HTML attributes, CSS tokens, and JavaScript syntax; text searches alone miss entity escapes, CSS escapes and computed access. If a dependency or state access cannot be established, stop before upload and name it. Do not execute untrusted source to decide these checks. Ordinary network hyperlinks also fail W2; do not silently rewrite their destination.

Create `presentation: { form: whole-deck }`, the file's `<title>` as H1 (use the supplied filename stem if absent), and **all** the HTML in one `html` fence. Escape Markdown metacharacters in the title. Choose a backtick delimiter strictly longer than every backtick run in the HTML; add a delimiter newline without consuming an authored final newline. Retain HTML comments, scripts, hidden nodes, attributes and internal notes. The frame supports html/body `id`, `class`, `style`, `lang`, `dir`, `title`, `role`, `hidden`, `inert`, `tabindex`, `translate`, `aria-*`, and `data-*` except shell-owned `data-deck-*`. Classes merge with shell classes; inline declarations override matching preview defaults while keeping other shell declarations. Other html/body attributes (including event handlers and resource attributes) are retained in stored source but are not installed in the live frame: list each unsupported attribute before upload and surface the frame diagnostic. Restructure explicitly if it affects fidelity; never claim that attribute rendered. Nothing inside that block is private. Read back after finalizing the upload before reporting a document link.

Before inserting any adapter, inspect every source section for an authored `hidden` attribute, regardless of its value (including `hidden="false"` or `hidden="until-found"`). Any such attribute disqualifies adapter insertion: preserve it and the source navigation; report that the host cannot count or select internal slides. Do not clear or override authored `hidden` to make a deck navigable.

An optional adapter is a small, source-specific script calling `strata.deck.registerAdapter({ count, current, goTo })`. Use an existing index getter and synchronous navigation function or documented hash mapping; never guess names or infer an index from visual appearance. `count()` must return a positive integer; `current()` is zero-based; `goTo(index)` synchronously selects that index. Guard registration with `strata.deck.active` so the original HTML preview still works. Insert the script before the actual closing body element using parsed source offsets, not a string replacement that might hit a script literal. Verify first/last navigation and the count in the real frame. Without a usable adapter, preserve internal navigation and report that the host cannot count or select internal slides.

## Gate two: deterministic eligibility procedure

This is a conservative, finite syntactic procedure, not a proof about arbitrary JavaScript. Run it on the exact gate-one artifact. Keep the original bytes, parse with an HTML5 parser and source locations, and parse CSS and ECMAScript 2022 scripts without executing them. Reject parser errors other than the HTML5 `missing-doctype` diagnostic, and repairs that change section boundaries, as `cannotEstablish` under S1. A missing doctype alone is accepted; preserve the original doctype (or its absence) and resulting document mode in every isolated frame. Unsupported syntax is `cannotEstablish`, never a guessed pass. Parser availability and successful completion are preconditions: parser absence, timeout, or infrastructure failure means **procedure not executed**, distinct from `pass`, `fail`, and `cannotEstablish`. Report the failed precondition, emit no eligibility verdict or S1–S5 rows (discard partial rows), and stop before splitting. Rerun the complete procedure once the precondition is restored. A coding agent may write a throwaway checker using its available parsers; no checker is shipped with this skill.

On a completed execution, report **all five rows in order**, with `pass`, `fail`, or `cannotEstablish`. A rejected row names its stable S-number, the element's one-based source line/column, section/script ordinal, and the rejected construct. For AST diagnostics, visit children before their parent, then choose the rejection with the earliest source offset; at the same offset choose the deepest node. Resolve any remaining tie by AST field order. For non-AST diagnostics, use element source order. When S1 cannot identify sections, still check independent assets/styles and mark section-dependent rows `cannotEstablish: section topology unavailable`. All rows must pass to split. The same bytes under this procedure have the same result; elapsed time, model confidence, browser behavior and a previous verdict are not inputs. Rerun after every source or adapter edit.

1. **S1 — one section per slide.** Ignore comments and whitespace-only text. Body children must be sections plus optional styles/scripts, OR exactly one other container whose children are sections (again ignoring comments/whitespace), with every remaining body child a style/script. There must be at least one section. No nested slide sections, text outside this topology, duplicate IDs, template/shadow content, or parser-repaired section boundaries. An unsupported or ambiguous topology is `fail`. Record each section's exact source range, original order, attributes and ancestor chain. Do not select all descendant sections and hope they are slides.
2. **S2 — styles global or per section.** Every style is a body child or has exactly one owning slide section. A head/container style or any `link[rel~=stylesheet]` is `fail`. Parse every style and style attribute. Retain each body style at its original position relative to the carried section (before or after its ancestor container), preserving total style order. A section-owned stylesheet must not match another section or its descendants; such cross-section effects cannot establish S2. Preserve html/body/container attributes and ancestry by repeating their shells around the single carried section; a wrapper is not another slide. A rule that depends on an absent sibling, section count/order (`+`, `~`, positional pseudo-classes), `:has`, or content/IDs in another section is `cannotEstablish`. Only type/universal/ID/class/attribute selectors, descendant/child combinators, selector lists, `:root`, `:hover`, `:focus`, `:focus-visible`, `:active`, `:disabled`, `:checked`, and `:is`/`:where`/`:not` over those selectors are accepted. An ID or attribute value must resolve within that section or its repeated shell. Unlisted selectors, CSSOM access from script, stylesheet mutation, and animation/timeline declarations are also `cannotEstablish`. Do not drop arbitrary selectors called `.active` or `.slide`: only remove declarations explicitly identified as navigation effects in S3, keeping any unrelated declarations. This closes the gap between legal style placement and a style retaining its meaning after isolation.
3. **S3 — decidable scripts.** Give every executable site an owner: body-level navigation or one section. Include inline event handlers, script URLs, module scripts, and scripts in foreign/template content. External script source is `cannotEstablish` (even a W3 library); head scripts and inline event handlers are `cannotEstablish`. Inert `application/json` script data stays with its owning section and is not executable; its use must still satisfy the lookup rules. All executable scripts must meet the accepted syntax below. Report the first rejected AST node at its source location as `cannotEstablish`, including shared helpers, computed selectors and sibling reads. Never execute a script to find out what it selects.
4. **S4 — self-contained assets.** Inspect parsed URL attributes (`src`, `href`, `srcset`, SVG `href`/`xlink:href`, `poster`, `data`, `action`, `formaction`), CSS URL/import tokens, and JavaScript `fetch`, `import()`, `new URL` and resource assignments. HTML entities and CSS escapes must be decoded before classification; parse `srcset`, do not split data URIs on commas. Only `data:` or a nonempty fragment resolving in the same isolated section or repeated shell passes. HTTP(S), protocol-relative, file-relative, `blob:`, empty references, a base URL, and cross-section fragments are `fail`. A computed asset reference is `cannotEstablish`. An external script fails S4 even if S3 already cannot establish its behavior. W3's library exception belongs to gate one only.
5. **S5 — a headline per section.** Read the section's first h1–h3 in tree order; use its nonempty trimmed text, otherwise a nonempty trimmed `data-title` on the section. No such text is `fail`. Collapse HTML whitespace, preserve Unicode and escape Markdown metacharacters. A later slide whose headline starts with `Appendix` (case-insensitive, after the grammar's shared whitespace trim) is `fail`: H2 would end the deck. Offer to rename it explicitly rather than silently lose that slide. A headline with structured children is `cannotEstablish` until the agent restructures it: shell injection uses textContent and would discard that structure.

### Accepted script syntax (S3)

Use an AST and lexical binding table, not substring allow/deny lists. Parse scripts as strict source; reject parse errors. Each script must be one immediately invoked function expression or block with `const`/`let` declarations, so its state never becomes a global binding. Function declarations/arrow callbacks may be nested inside it. Bindings are script-local; resolve every identifier to its declaration before accepting a call. A declaration in another script is a **shared helper**, even if it looks pure. No undeclared reads or writes except the exact receiver chains below.

The finite statement set is declarations, blocks, expression statements, `if`, and `return`. Expressions may be primitive literals, lexical identifiers, arrays of primitives, arithmetic/comparison/boolean/conditional expressions, and direct calls to functions declared in the same script. No destructuring, spread, prototypes, getters/setters, reflection, aliasing a host object/method, dynamic property names, recursion, loops, timers, exceptions, generators, async functions or dynamic code. An unlisted AST form is `cannotEstablish`; do not interpret it optimistically.

| Script owner | Accepted DOM operations |
| --- | --- |
| Section | `document.getElementById("literal")`, `document.querySelector("literal")`, or `document.querySelectorAll("literal")`. Resolve against the original parsed document: the result must be nonempty and every matching node must belong to that section. Store a result in a local binding if needed. A single node may read/write `textContent`, `hidden`, `style.<literal property>` or call `classList.add/remove/toggle` with literal class names. A list may be accessed with a literal integer index in range. |
| Navigation | A body script may obtain one `document.querySelectorAll("section")` result, or a literal class selector matching **exactly all** identified sections in source order. It may read its length, index it with a local integer slide index, and set a selected node's `hidden` property or toggle a literal active class. Local arithmetic may advance/clamp/wrap the index. It may register `document.addEventListener("keydown"/"click", callback)` or `window.addEventListener("hashchange", callback)`; the event may read `key`. `window.location.hash` may be read/written using local primitive values. No other DOM access or effects. |

Property access is accepted only on those tracked node/list/event bindings, local primitive arrays, and the exact receiver chains above. Do not accept computed member access just because its result happened to be local in one run. `eval`, `Function`, `document.write`, non-hash location access, `parent`, `top`, `open`, global assignment, parent/sibling traversal, network calls, and calls on unknown receivers are always outside S3. Literal embedded-resource calls still require an explicitly modeled receiver; S4 passing does not make a script decidable. A source-specific adapter is subject to S3 like any other script. The sole exception is the validated section adapter below: recognition depends only on the supplied file, never on who inserted it or a prior gate/run. A marker alone grants no exception. Never remove unrecognized scripts to get a pass.

### Validated section adapter (version 1)

For a deck with S1 topology and no source section bearing an authored `hidden` attribute, an agent may insert this exact element as a direct body child. Recognize it only if there is exactly one element with `data-strata-section-adapter`, its only attribute is `data-strata-section-adapter="1"`, and its complete source range is byte-for-byte the following UTF-8/LF template (including the line breaks inside the element). `document.querySelectorAll("section")` must match exactly the S1 sections. If any source section has `hidden` (any value), the validated-adapter exception returns S3 `cannotEstablish`, even when the template bytes match; report the first hidden section in source order. This check uses the parsed source before executing scripts, never the live DOM. There must be no other body navigation script; each section's `hidden` attribute is the adapter's sole visibility effect. Existing section-local scripts and CSS still undergo all S1–S5 checks; competing visibility effects cannot establish S2. Unknown versions, duplicate markers, added attributes, or any changed script byte cannot establish S3; they never authorize removal.

```html
<script data-strata-section-adapter="1">
{
  const slides = document.querySelectorAll("section");
  let index = 0;
  const goTo = (next) => {
    index = next;
    slides.forEach((slide, ordinal) => { slide.hidden = ordinal !== index; });
  };
  if (strata.deck.active) {
    goTo(0);
    strata.deck.registerAdapter({ count: () => slides.length, current: () => index, goTo });
  }
}
</script>
```

A validated instance passes S3 as navigation and is removed only from the split copy, where carried sections retain their source attributes; validation has established that none has authored `hidden`. Never strip `hidden` from a source section. Keep it byte-for-byte in whole-deck. Apply this rule identically to an original file, a just-adapted file and a re-import of the same adapted bytes. Record the template version and source range, not provenance. Other source-specific adapters remain available for whole-deck, but do not receive this exception.

For accepted navigation, record the specific selectors/classes and visibility declarations it owns. A body script with any other effects is not navigation. If removal cannot be separated from slide drawing (for example `.active` also changes typography), S2 cannot establish. This is a decision about the original source, not whatever state a browser happened to have reached.

## Splitting a file that passes

Prepare the entire new artifact locally before writing. The split creates a separate document and preserves the whole-deck document and original file.

- First section → H1 cover **and its HTML block**; each later section → H2 and one HTML block. No extra cover. Assert the parsed slide count equals the source section count before upload.
- Carry each entire section from its original source range. Keep its tag, every attribute, nested content, code examples, comments, IDs, local style and local script. Do not convert HTML prose into Markdown or split on text that looks like a heading/fence inside a section.
- Prepend `<!-- slide: … -->` inside each fence (escape `--` and `>` in the marker). Add a stable `s-001`, `s-002`, … ID only to sections without one; avoid collisions with **all** authored IDs by adding a numeric suffix. On the headline element keep its tag/attributes, add `data-deck-headline`, and remove its text; the live shell now supplies it. For data-title-only sections prepend a matching empty h1/h2 with that attribute. Keep the heading text in Markdown, not twice in the visual.
- Repeat global styles in their original body-child positions relative to the retained section or its container: earlier styles stay before it, later styles stay after it. Never hoist later global styles across local styles. Removing other sections must not reorder any surviving stylesheet. Repeat html/body/container shells and non-executable head metadata needed by the source, excluding the document title. Retain local styles in their original position. Drop only the navigation script and its proven visibility effects; restore each isolated section to the navigation-visible state. Preserve every unrelated CSS declaration. Never classify an authored `hidden` attribute as a removable navigation effect.
- Additionally map plainly named top-level `:root` variables with [theme-import.md](theme-import.md)'s eight-token table into `css name=deckTheme` under `## Appendix`. Existing `--deck-*` names win; otherwise map `--background`→`--deck-bg`, `--text`→`--deck-fg`, `--accent`→`--deck-accent`, `--muted`→`--deck-muted`, `--font-heading`→`--deck-font-heading`, `--font-body`→`--deck-font-body`, `--padding`→`--deck-padding`, `--radius`→`--deck-radius`. Preserve the original declarations too. Use the last declaration in source order; report ambiguous semantic aliases as unmapped instead of guessing. Do not invent provenance or a lock. For existing presentation Markdown, preserve the appendix and each fence's `name`, `uses`, layout and theme provenance attributes unchanged.
- Choose safe delimiters independently for every fence, preserving final newlines. Parse, serialize, and parse the complete Markdown through the document grammar. Compare each section's code-block body and attributes, all IDs, local scripts, binding attributes and theme attributes. Only the documented section/headline/navigation edits may differ from source.
- Report hardcoded numeric text with section and element locations as binding candidates. Do not automatically turn dates, labels or measurements into data sources.

Show five completed check results before creating the split document. On **procedure not executed**, report the failed precondition with no eligibility verdict, preserve whole-deck, and rerun after recovery. On `fail` or `cannotEstablish`, name the rule and source location, keep whole-deck, and offer either keeping it or restructuring the source and rerunning the procedure. Explain what whole-deck lacks: per-slide comments/suggestions, separate private presenter notes, thumbnails, per-slide findings and cheap section edits. Nothing in its HTML is private.

After creating the split, read both documents back and check the slide count, whole-section bytes and fence attributes. Drive the real whole-deck and split frames at 1280×720 and 960×540, navigate each original section, and compare corresponding screenshots with a stated pixel tolerance. Also inspect headline injection, clipping and local scripts. Source/round-trip checks establish structural fidelity; **only the browser comparison establishes visual fidelity**. Report that assertion as unexercised when the browser or source navigation is unavailable. Do not delete whole-deck until the person explicitly authorizes it after review.

## Out of Scope

- A compiled importer, dedicated API, or script shipped with the skill: LLD 1 assigns this source transformation to the reader's coding agent. Existing Markdown uploads already persist through the canonical document pipeline.
- Automatic extraction of numeric bindings or inference of arbitrary JavaScript behavior: labels and dependencies require source restructuring or user judgment. Rejection retains a useful whole-deck document.
- PPTX fidelity and editable PowerPoint conversion: the existing office converters produce ordinary documents and do not implement this HTML contract.

## File upload sequence

Use `edit_document`'s existing upload actions for source that is already a local file:

1. Measure the finalized file's byte length (`wc -c < deck.md`), after any adaptations.
2. Call `edit_document` with `action: presignUpload`, `contentLength`, and either the existing `documentId` for replacement or `title` plus an optional actual `folderId` for creation. Select the destination audience intentionally. Replacement through `finalizeUpload` is a full-content update with no expected-version precondition and can overwrite collaborator changes without a version-conflict error. The PUT only stages bytes; replacement happens at finalization. Internal WAL conditional writes do not check the version you read. Prefer small, uniquely anchored `edit` calls for a live deck, subject to the task-local matching and rewrite-fallback limits in [SKILL.md](../SKILL.md#editing-while-others-may-be-working). No MCP body-write path guarantees safety against a concurrent editor. If the deck appears actively edited, tell the user and coordinate a pause or prepare a separate copy. If replacement is unavoidable, re-read immediately before finalizing, compare `documentVersion` with the version used to prepare the file, and abort if it moved. An unchanged version narrows the race window but does not close it.
3. PUT the exact file bytes to the returned `uploadUrl`, supplying all returned `requiredHeaders`. Use binary file upload, not a shell-interpolated text body. Do not log or publish the signed URL.
4. Call `edit_document` with `action: finalizeUpload` and the returned `uploadId` only after the PUT succeeds. Finalization is idempotent. It checks the size and requires valid UTF-8 Markdown; it returns `documentId`, `bytes`, and `created`.
5. Read the resulting document back. Compare frontmatter, slide boundaries, IDs, theme provenance, bindings, notes, and appendix resources against the intended source. Check actual visual output where the current client offers it. Report unsupported rendering and import losses plainly.

Respect the upload response's expiry and organization size limit. If upload/finalization fails, surface the actual error and retain the source file. Do not claim that a successful PUT alone created the document.

## Export availability

Discover the connected `export_presentation` schema before calling it. Current servers provide standalone HTML and PDF, with an expiring download URL. Whole-deck HTML is rejected because its internal notes cannot be stripped; an eligible split is the path to an audience-only export. Report the actual rejection and keep the source. Do not turn off presentation settings or claim notes were removed to bypass this boundary.

PDF uses the document owner's capture allowance; HTML is unmetered. Use only formats advertised by the connected tool, and report success only after receiving the result. PPTX and ordinary document PDF/DOCX conversion do not establish presentation fidelity.
